Leaf field names the server renders only when named explicitly — never pulled in by a parent path or the * wildcard, because each needs Move type-layout resolution on the node (and display a display-index lookup).

Passed as the exceptions to FieldMaskTree::add_field_path_with_exceptions and used by crate::field_mask_normalize, so one of these leaves survives alongside its parent path ([output_objects, output_objects.json]) instead of being collapsed into the bare parent — which the server would then not render.

The exception match looks at every path component, not just the leaf (so a sub-path like display.fields is kept too). That relies on these names denoting only server-rendered fields within the response messages a read mask selects. The request-side InputArgument.json shares the name but is never a read-mask target, so it is not affected.
